## Model boundaries and correspondence

The scheduler model defines a stable minimum charge among unfinished targets.
The corpus checks that public Rust entry point, including all-stopped, ties and
overshoot debt. Executable negative witnesses reject ignoring stopped status or
choosing the first target despite a lower charged peer.

The admission examples model positive remaining budget and interruption; the
original-preservation theorem models append-only derivative state. These two
claims have **model evidence only** here. This adapter does not compare campaign
clock accounting or filesystem persistence with Lean. Existing product tests own
those implementation boundaries. The model excludes collection/setup duration,
OS timing, worker lifecycle, transport, native memory enforcement, minimization,
filesystem failures and adversarial simultaneous writers.

The fuzz target checks eligibility, global minimum charge, stable tie order and
all-stopped behavior using 128-bit charges. Equal lengths of charge/stopped
vectors are a caller invariant: the campaign creates both for the same targets.
Mismatched-slice API behavior is outside this target's claimed coverage. Wire
parsing is private and is not exercised by this scheduler target.

## Implementation self-review passes

1. Scope and provenance: use product `python/`, root Rust and real CLI rather
   than claiming experimental tests establish product behavior. All reused
   action SHAs and tool pins come from existing repository workflows.
2. Native matrix: configure Ubuntu/macOS/Windows × CPython 3.14/3.15 with
   fail-fast disabled, per-job deadlines and frozen Python dependency sync.
   Separate Python strict checks from Rust checks and preserve failed evidence.
3. Permission/side effects: read-only token permissions, checkout credentials
   disabled, SHA-pinned actions, no release/publish steps. Smoke writes only a
   temporary test/store and a named evidence directory.
4. Executable correspondence: found the first `lake build` did not select an
   executable by default; added explicit default targets. Generated expectations
   and a standalone Rust adapter now compare the actual scheduler API.
5. Resource bounds: fuzz time, input length, allocation and RSS are finite;
   dated nightly and dependency lockfiles are committed. Workflow retains fuzz
   corpus and failure inputs. Lean has finite 217-case generation and heartbeat
   bounds, not an exhaustive model of arbitrary campaigns.

## Test/infrastructure self-review passes

1. Smoke sensitivity: a successful process alone is insufficient. Workflow
   additionally requires JSON schema version, nonempty targets and positive
   attempts. A no-op campaign fails that check.
2. Scheduler sensitivity: include tie, stopped, overshoot and empty cases;
   Lean contains explicit witnesses excluding two plausible broken schedulers.
3. Oracle provenance: `--check` compares generated bytes with the committed
   corpus; the adapter translates TSV and calls Rust without rewriting results.
4. Fuzz sensitivity: assertions inspect every eligible target and tie order;
   input chunks independently encode full-width charges and stopped flags.
   No finding is inferred from an unexecuted fuzz command.
5. CI syntax and trust: actionlint/shellcheck and offline zizmor pass. Found
   formatting differences in both new nested Rust packages; formatted them and
   reran checks. Matrix scheduling remains an external acceptance action.
